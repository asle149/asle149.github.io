# 1. 멱등성 프로듀서
멱등성(idempotence) = 여러 번 연산을 수행해도 동일한 결과가 나오는 성질
멱등성 프로듀서 = 동일한 데이터를 여러 번 전송해도 카프카 클러스터에 단 한 번만 저장

| 수준                         | 뜻                  | 유실      | 중복          |
| -------------------------- | ------------------ | ------- | ----------- |
| At most once (최대 한번)   | 한 번 보내고 끝 (재시도 없음) | 있을 수 있음 | 없음          |
| At least once (적어도 한번) | 성공 확인될 때까지 재시도     | 없음  | 있을 수 있음 |
| Exactly once (정확히 한번)  | 딱 한 번만 적재됨         | 없음      | 없음          |
-> 기본 프로듀서의 동작 방식은 멱등성 프로듀서!

### 멱등성 프로듀서

![[Pasted image 20260720115846.png|334]]![[Pasted image 20260720115852.png|335]]

멱등성 프로듀서는 데이터를 보낼 때 PID(프로듀서 고유 ID)와 시퀀스 넘버(SID)를 함께 전달함
브로커는 PID와 시퀀스 넘버를 확인해서, 동일한 메시지의 적재 요청이 또 와도 단 한 번만 적재
- 비멱등성: V1 전송 → acks 유실 → 재전송 → V1, V1 (중복!)
- 멱등성: V1(seq=0) 전송 → acks 유실 → 재전송해도 여전히 seq=0 → 브로커: 이미 있네 → V1 한 개만 

### 멱등성 프로듀서의 한계
**멱등성 프로듀서는 동일한 세션에서만 정확히 한번 전달을 보장 (세션 = PID의 생명주기)**
애플리케이션에 이슈가 생겨 종료 후 재시작하면 PID가 달라짐 
→ 같은 데이터를 보내도 브로커는 "다른 프로듀서가 다른 데이터를 보냈다"고 판단 
→ 중복 적재 가능
장애가 발생하지 않을 경우에만 정확히 한 번 적재를 보장함

### OutOfOrderSequenceException
브로커는 시퀀스 넘버가 0, 1, 2, … 순서대로 올 것을 기대함 예상한 번호와 다른 번호(예: seq=0 다음에 seq=2)가 오면 OutOfOrderSequenceException 발생함


# 2. 트랜잭션 프로듀서
### 트랜잭션
다수의 파티션에 데이터를 저장할 때, 모든 데이터에 대해 동일한 원자성(atomicity)을 만족시키기 위해 사용. 
원자성 = 다수의 데이터를 동일 트랜잭션으로 묶어 전체가 처리되거나, 전체가 처리되지 않도록 하는 것. 
ex) DB 트랜잭션의 "all or nothing"과 같은 개념

![[Pasted image 20260720120851.png|439]]

사용자가 보낸 데이터를 파티션에 저장할 뿐 아니라, 트랜잭션의 시작과 끝을 표현하는 **트랜잭션 레코드(COMMIT)** 를 한 개 더 보냄
토픽A-파티션X에 `V1 V4 COMMIT`, 토픽A-파티션Y에 `V2 COMMIT`, 토픽B-파티션Z에 `V3 COMMIT` 
-> **여러 토픽·파티션에 걸친 데이터**가 한 트랜잭션으로 묶임.
